# SDD — A IA como assistente de segurança

## Origem

PDF §6 (Como funcionará a IA), §8 (IA: OpenAI ou Gemini, prompt fixo, dados mascarados),
§13 Etapa 6.

## Contexto

O PDF é categórico sobre o papel da IA:

> "A IA será um **assistente de segurança**, não o cérebro principal do sistema."

Ela entra **depois** que o risco já foi decidido pelas regras. Explica, sugere, descreve —
mas não decide e não age. E nada sai desta plataforma em direção a um provedor externo sem
passar antes pelo mascaramento.

## Requisitos funcionais

A IA **pode**:

- RF-1: Explicar a vulnerabilidade.
- RF-2: Informar o possível impacto.
- RF-3: Explicar por que o risco foi priorizado.
- RF-4: Sugerir a remediação.
- RF-5: Criar uma descrição pronta para ticket de correção.

A IA **não pode**:

- RF-6: Alterar código automaticamente.
- RF-7: Fazer commit.
- RF-8: Aprovar a correção sozinha.
- RF-9: Mudar a classificação sem autorização.
- RF-10: Executar ataques.

Antes de qualquer envio, o sistema mascara: IPs, tokens, senhas, chaves de API e nomes
internos. O exemplo do próprio PDF:

```
IP real: 192.168.0.10
Enviado para a IA: [IP_MASCARADO]
```

- RF-11: Provedor é OpenAI ou Gemini, escolhido por configuração.
- RF-12: O prompt é fixo — a estrutura não varia com a entrada.

## Considerações de segurança

- **Esta é a superfície de vazamento do produto.** Todo texto que sai passa por
  `mascarar()`. Campo novo no prompt significa campo novo passando pelo masking.
- A chave de API vem só do ambiente, nunca do código nem do banco.
- A plataforma funciona sem chave: apenas as explicações ficam indisponíveis, com mensagem
  clara.
- A resposta do modelo é texto exibido. Não é executada, não é interpretada como comando,
  não altera risco nem status.

## Critérios de aceitação — testáveis

### Mascaramento (PDF §6)

- **AC-IA-01** — Dado um texto contendo um endereço IPv4, quando mascarado, então o IP é
  substituído por `[IP_MASCARADO]`.

- **AC-IA-02** — Dado um texto contendo um token JWT ou um cabeçalho `Bearer`, quando
  mascarado, então o token é substituído por `[TOKEN_MASCARADO]`.

- **AC-IA-03** — Dado um texto contendo uma senha atribuída a variável (`password=`,
  `senha:`), quando mascarado, então o valor é substituído por `[SENHA_MASCARADA]`.

- **AC-IA-04** — Dado um texto contendo uma chave de API atribuída a variável, quando
  mascarado, então o valor é substituído por `[API_KEY_MASCARADO]`.

- **AC-IA-05** — Dado uma lista de nomes internos configurada, quando o texto é mascarado,
  então cada ocorrência literal é substituída por `[NOME_MASCARADO]`.

- **AC-IA-06** `[extensão]` — Dado um texto contendo endereço de e-mail, quando mascarado,
  então é substituído por `[EMAIL_MASCARADO]`.

- **AC-IA-07** `[extensão]` — Dado um texto contendo endereço IPv6, quando mascarado,
  então é substituído por `[IP_MASCARADO]`.

- **AC-IA-08** — Dado um texto sem nenhum dado sensível, quando mascarado, então é
  devolvido inalterado.

- **AC-IA-09** `[proibição]` — Dado dados técnicos contendo IP, token e senha, quando a
  análise é solicitada, então o prompt efetivamente entregue ao provedor **não** contém
  nenhum dos três valores originais.

### O que a IA produz

- **AC-IA-10** — Dado uma vulnerabilidade classificada e um provedor configurado, quando a
  análise é gerada, então a resposta traz explicação, impacto, justificativa da
  priorização, sugestão de correção, forma de validação e descrição de ticket.

- **AC-IA-11** — Dado a análise gerada, quando o detalhe da vulnerabilidade é consultado,
  então os textos da IA aparecem junto com a data de geração.

- **AC-IA-12** — Dado o prompt montado, quando inspecionado, então ele informa o risco e a
  justificativa **já decididos** e instrui explicitamente que a classificação não deve ser
  questionada nem alterada.

### As proibições do PDF §6

- **AC-IA-13** `[proibição]` — Dado o módulo de IA, quando suas dependências são
  inspecionadas, então ele **não** importa `risk_engine` nem `correlator`: não há caminho
  para a IA participar da decisão de risco.

- **AC-IA-14** `[proibição]` — Dado que a IA respondeu, quando a análise é gravada, então
  o nível de risco e a justificativa da vulnerabilidade permanecem exatamente os que as
  regras haviam definido.

- **AC-IA-15** `[proibição]` — Dado que a IA respondeu, quando a análise é gravada, então
  o status de acompanhamento da vulnerabilidade **não** é alterado — a IA não aprova
  correção.

- **AC-IA-16** `[proibição]` — Dado o prompt montado, quando inspecionado, então ele não
  contém termos que induzam ação no repositório ou no alvo (`commit`, `push`,
  `pull request`, `criar branch`, `executar comando`, `alterar arquivo`,
  `aprovar a correção`, `executar ataque`).

- **AC-IA-17** `[proibição]` — Dado o módulo de IA, quando suas dependências são
  inspecionadas, então ele não importa `subprocess`, `os.system` nem biblioteca de
  execução: não há como a IA executar nada.

### Provedores e falhas

- **AC-IA-18** — Dado `AI_DEFAULT_PROVIDER=openai` com chave configurada, quando a análise
  é gerada, então o provedor OpenAI é usado.

- **AC-IA-19** — Dado `AI_DEFAULT_PROVIDER=gemini` com chave configurada, quando a análise
  é gerada, então o provedor Gemini é usado.

- **AC-IA-20** — Dado que nenhuma chave está configurada para o provedor selecionado,
  quando a análise é solicitada, então a API responde 503 com mensagem explicando que a IA
  não está configurada — e o restante da plataforma continua funcionando.

- **AC-IA-21** — Dado que o provedor falhou, quando a análise é solicitada, então a API
  responde 502 e a vulnerabilidade continua com risco, justificativa e status válidos.

- **AC-IA-22** `[extensão]` — Dado que a resposta do modelo veio envolvida em cerca de
  bloco de código, quando interpretada, então as cercas são removidas e o JSON é lido.

> **Por que o SDK do Gemini é um critério e não um detalhe.** O `google-generativeai`
> teve o suporte encerrado em 30/11/2025 e depende de `protobuf`, que não carrega no
> Python 3.14 — `import google.generativeai` levanta `TypeError: Metaclasses with custom
> tp_new are not supported`. O import é preguiçoso e o caminho do Gemini não tinha SDK
> falso nos testes, então a suíte ficava verde com o provedor morto. Fixar o SDK como AC
> é o que impede a mesma armadilha de voltar.

- **AC-IA-27** `[extensão]` — Dado que o provedor Gemini está configurado com uma chave,
  quando a análise é gerada, então a chamada acontece pelo SDK `google.genai` — um
  `Client(api_key=…)` seguido de `models.generate_content(model=…, contents=…)` — e o
  texto da resposta é devolvido; o SDK aposentado `google.generativeai` não é importado
  em nenhum ponto do produto.

### Modelo configurável — nenhum nome fixado no código de chamada

> Provedores aposentam modelos sem aviso. Este projeto já foi mordido duas vezes: o
> `gemini-1.5-flash` original saiu de circulação e o `gemini-2.0-flash` que o substituiria
> foi desativado logo depois. Nos dois casos o sintoma é "modelo inválido" com uma chave
> perfeitamente válida. Por isso o nome do modelo é **configuração**, não constante.

- **AC-IA-23** `[extensão]` — Dado `OPENAI_MODELS` configurado no ambiente e o primeiro
  modelo da lista indisponível para a chave, quando a análise é gerada, então o provedor
  tenta o próximo modelo **da lista configurada**, e não da lista padrão do projeto.

- **AC-IA-24** `[extensão]` — Dado `OPENAI_MODEL` ou `GEMINI_MODEL` configurado, quando o
  provedor é construído, então usa exatamente esse modelo: escolha explícita do usuário
  não é substituída em silêncio, e a falha aparece.

- **AC-IA-25** `[extensão]` — Dado o provedor e o modelo configurados, quando a rota de
  saúde é consultada, então informa qual provedor e qual modelo serão usados — descobrir
  isso é a parte difícil de diagnosticar quando um modelo é aposentado.

- **AC-IA-26** `[proibição]` — Dado o módulo que constrói os provedores, quando inspecionado,
  então nenhum nome de modelo aparece literalmente nele: os nomes vêm da configuração ou
  das listas padrão declaradas em um único lugar.

- **AC-IA-28** `[extensão]` — Dado que o primeiro modelo candidato não é aceito pela chave,
  quando o provedor **Gemini** gera a análise, então o próximo candidato da lista é
  tentado; e, com `GEMINI_MODEL` fixado pelo usuário, o erro aparece em vez de haver
  substituição. É o que `AC-IA-E4` já prova para o OpenAI — a ausência do equivalente do
  lado do Gemini é justamente o que deixou a quebra do SDK passar despercebida.

## Casos de borda

- **AC-IA-E1** — Dado que a resposta do provedor não é JSON válido, quando interpretada,
  então um erro de provedor é levantado e nada parcial é gravado.

- **AC-IA-E2** — Dado que a resposta é um JSON sem algumas das seis chaves, quando
  interpretada, então as chaves ausentes viram texto vazio, sem quebrar.

- **AC-IA-E3** — Dado uma vulnerabilidade inexistente, quando a análise é solicitada,
  então a API responde 404.

- **AC-IA-E4** `[extensão]` — Dado que o modelo configurado foi aposentado pelo provedor,
  quando a análise é gerada, então o próximo modelo candidato é tentado; se o usuário fixou
  o modelo explicitamente, o erro aparece em vez de haver substituição silenciosa.

## Contrato de API

| Método | Rota | Corpo | Resposta | Erros |
|---|---|---|---|---|
| POST | `/api/vulnerabilidades/{id}/analise` | — | `VulnerabilidadeDetalhe` com `analise_ia` | 401, 404, 502, 503 |

A análise é gerada **sob demanda**, não durante o upload: um relatório grande faria dezenas
de chamadas e deixaria o envio lento, e nem toda vulnerabilidade precisa de explicação.

## Restrições conscientes

- O mascaramento é por expressão regular. Cobre as categorias que o PDF lista, mas formato
  incomum de token pode escapar. Nomes internos precisam ser configurados em
  `PRIDE_INTERNAL_NAMES` — não há como adivinhar "servidor-prod-01".
- As listas padrão de modelos envelhecem, e é por isso que existem `OPENAI_MODELS` e
  `GEMINI_MODELS`: quando todos os padrões caírem, a saída é configurar, não editar
  código. O projeto não consulta o catálogo do provedor para descobrir modelos novos
  sozinho — só lista os aceitos na mensagem de erro do Gemini, como ajuda de diagnóstico.
- Sem cache de resposta. Pedir a análise duas vezes chama o provedor duas vezes.
- Sem streaming. A resposta chega inteira ou não chega.

## Validação real

- Fluxo: configurar `OPENAI_API_KEY` ou `GEMINI_API_KEY` no `.env` → abrir uma
  vulnerabilidade → pedir a análise da IA.
- O que deve aparecer: os seis blocos de texto, e a justificativa da priorização coerente
  com o motivo que o sistema já havia calculado.
- Critério: o nível de risco exibido é o mesmo antes e depois de gerar a análise.
